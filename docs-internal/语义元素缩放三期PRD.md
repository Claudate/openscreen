## 一、背景与目标

### 1.1 三期解决什么（承接一二期遗留）

| 一二期遗留编号 | 描述 | 三期对应动作 |
|---|---|---|
| **K3**（一期登记） | Electron（VSCode/Slack/Notion/Cursor）、浏览器网页、Metal/canvas（Figma）AX 返回空 → 语义缩放不生效，只能退坐标聚类 | **S1 视觉兜底 MVP**（OmniParser 检测器 + ort/CoreML） |
| 体验盲区（路线图新立项） | 长页面滚动演示时，已生成的 zoom 段定位静止、内容滚走 → 错位 / 晕动 | **S2 滚动跟随（MVP = 滚动退避）** |
| 鲁棒性盲区（路线图新立项） | 多显示器：录制屏外点击、跨屏窗口、混合 DPI 场景的语义矩形正确性未系统验证 | **S3 多显示器语义缩放正确性** |

### 1.2 为什么值得做

- **S1 是覆盖率核心缺口**：录屏教程的大头场景恰是浏览器和 Electron 应用（写代码、用 SaaS、做网页演示）。一二期的语义缩放在这些场景全部静默降级——补上视觉兜底，差异化才覆盖主流内容创作场景。
- **S2/S3 是「永不退步」的延伸**：滚动晕动与多屏错位是少数会让自动缩放**比不开还差**的场景，必须主动设防，守住兜底铁律。

### 1.3 产品目标与北极星

- **主目标**：Electron / 浏览器场景下语义缩放（携带有效元素矩形的段）从 0 提升到可用水平；滚动与多屏场景零「负体验」事件。
- **北极星指标**：全场景（原生 + Electron + 浏览器）自动缩放段中语义段占比 ≥ 70%（一期口径为原生 ≥ 60%）。
- **不可退让底线（继承一二期兜底铁律）**：视觉检测失败 / 滚动 / 多屏任一场景，行为自动退回二期现状（AX → 坐标聚类），只升不降。

## 三、现状核验结论（三期改造基线，逐项实测 `ba7c3dcae`）

> 每一条均经源码 / 配置实测，非推断。

### 3.1 视觉兜底的依赖红利（S1 基础已在仓库内）

- `crates/camera-effects/Cargo.toml` L17/L20/L23：**`ort = 2.0.0-rc.12` 已内置**，macOS 分支 feature = `load-dynamic + coreml`（Windows 为 `directml`）——视觉推理运行时**零新增 crate**。
- 预研报告已锁定模型路线：OmniParser YOLOv8 Nano icon_detect（约 6–12MB，AGPL 与 Cap 许可证兼容，预研已查证）；强 GPU 下 0.6–0.8s/帧 → 不可实时，仅点击触发。
- 二期 T5 已交付「点击占位入列 + 索引锁定 + `spawn_blocking` + channel 回填」异步并发模型（`crates/recording/src/cursor.rs`）——**S1 的异步推理直接复用同一模式**，把「AX 反查」换成「AX 反查失败 → 视觉推理」即可，时序零错配机制现成。

### 3.2 滚动事件采集（S2 需新增，实测为空白）

- `crates/recording/src/` 全目录 `rg -i 'scroll|wheel'` **零命中**——当前只采集 `CursorMoveEvent` / `CursorClickEvent` / `KeyPressEvent`（`cursor.rs` L4 import 实证）。
- 结论：S2 需要新增滚动事件类型与采集点；数据契约沿用一二期 `Option` / 新增集合字段的 serde 兼容铁律（旧录制无滚动数据 = 行为等于现状）。

### 3.3 多显示器坐标换算（S3 基础已在，验证缺口在边界）

- `crates/cursor-capture/src/position.rs`：`RawCursorPosition::relative_to_display(display)` 换算链（`physical_bounds` / `logical_bounds`，top-left origin）已是一二期 AX 矩形换算的同源链路；既有隔离测试含「多屏负坐标」用例（一期主控隔离 5 测试之一）。
- 缺口：录制屏**外**点击时 AX 全局坐标换算结果超出 `[0,1]` UV——下游 `is_meaningful()` 与 clamp 行为是否在所有分支正确过滤，未做系统化边界用例；混合 DPI（Retina + 1080p 外接）未验证。

## 四、功能规格

### 4.1 S1 视觉兜底 MVP（核心）

**触发与降级链（铁律）**：

```text
点击按下 → AX 反查（二期 T5 异步链路，0.25s 超时）
  ├─ AX 命中有效矩形 → 用 AX（微秒级，原生 App 主路径，不变）
  ├─ AX 失败/空 → 视觉兜底：点击瞬间帧局部 ROI → OmniParser icon_detect → 含点击坐标的最小检测框 → element_bounds
  └─ 视觉也失败/超时 → None → 坐标聚类（= 二期现状，永不退步）
```

**规格要点**：

1. **输入**：点击瞬间的录制帧（录制管线内存中现成，无需额外截屏权限），裁剪以点击点为中心的 ROI（建议 1/4 屏区域，降低推理耗时与误检）。
2. **推理**：`ort` 会话常驻（录制开始时惰性加载一次），macOS CoreML EP；`spawn_blocking` 异步执行，复用 T5 的索引锁定 + channel 回填，**采集节拍零阻塞**。
3. **选框**：检测结果中**包含点击坐标**的候选框取面积最小者（最具体的控件）；无包含框则取中心距点击点最近且距离 ≤ 阈值者；否则判失败。
4. **输出**：换算到与 AX 同一 UV 坐标系后写入 `CursorClickEvent.element_bounds`——**生成层 / 渲染层 / 调参面板零改动**（一二期数据契约直接复用，这是三期低风险的根本原因）。
5. **开放决策点（开工前架构师拍板）**：是否在数据层新增 `element_source: Option<ElementSource>`（`ax` / `vision`）标记来源——便于真机命中率分桶统计与问题归因；按一二期 serde 兼容铁律加 `Option` 字段，回滚零风险。
6. **预算约束**：模型文件 ≤ 15MB（随包分发或首次使用下载，开工前拍板）；点击后回填等待上限沿用 T5 排水机制（录制结束 1s 总余量内未回流即放弃）。

### 4.2 S2 滚动跟随（MVP = 滚动退避）

**产品定义（保守版，先做对再做炫）**：滚动密集时段内**主动拉远 / 抑制 zoom**，而不是让 zoom 视口对着已滚走的内容。

1. **采集**：新增滚动事件（时间戳 + 滚动量），macOS 由现有鼠标事件源旁路扩展；数据契约新增集合字段（serde default，旧录制为空 = 现状）。
2. **生成层**：聚类窗口内滚动量超过阈值 → 该时段标记「滚动密集」→ 已有 zoom 段提前结束 / 新 zoom 段抑制生成（具体参数真机校准）。
3. **渲染层零改动**：退避通过生成层段裁剪实现，不新增渲染分支。
4. **不做**：跟随滚动平移视口（二阶，见 2.2）。

### 4.3 S3 多显示器正确性

1. **屏外点击过滤**：换算结果超出 `[0,1]` UV 的矩形 / 中心点必须在采集层或生成层显式丢弃（补系统化边界用例：负坐标屏、右侧扩展屏、纵向排列屏）。
2. **混合 DPI**：Retina（2x）+ 外接 1080p（1x）组合下 AX / 视觉矩形换算一致性用例。
3. **跨屏窗口拖动**：点击时窗口所在屏与录制屏不一致时的行为定义：**录制屏外的点击一律不产生语义段**（正确性优先）。

## 五、关键设计决策

| 决策 | 选择 | 理由 |
|---|---|---|
| S1 模型路线 | OmniParser YOLOv8 Nano icon_detect（裁剪版） | 预研已对比锁定：体积小、ort/CoreML 现成、AGPL 兼容；不自训模型 |
| S1 触发时机 | 仅点击 + 仅 AX 失败时 | 推理不可实时；AX 命中场景零额外开销，原生 App 路径完全不变 |
| S1 数据出口 | 复用 `ElementBounds` 写回同一字段 | 生成 / 渲染 / UI 三层零改动，回归面最小 |
| S2 MVP 语义 | 退避（拉远/抑制）而非跟随 | 跟随依赖内容分析，错误跟随比不跟随更糟；退避是纯防御、稳赚不赔 |
| S3 行为定义 | 录制屏外点击不产生语义段 | 正确性优先于覆盖率；误放大到错误位置是「负体验」一票否决项 |

### A.2 同步节奏与分类处置

每个上游 release 发布后 **1 个工作日内**完成评估，按 diff 命中范围分三类：

| 类别 | 判定 | 处置 |
|---|---|---|
