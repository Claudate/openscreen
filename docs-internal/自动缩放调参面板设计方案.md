## 一、设计目标（一句话）

把 Cap 后端 `ZoomSegment` **已就绪但前端从未暴露**的 4 个可调字段（`glideSpeed`/`edgeSnapRatio`/`instantAnimation`/`glideDirection`），用**符合视频创作者心智的语义化 UI** 暴露在编辑器的缩放调参面板里——这是把 Cap 从 `Limited zoom` 拉到 Screen Studio Pro 级的**纯 UI 侧补全**（不依赖 Rust 编译，可独立落地）。

## 三、竞品对标（Screen Studio 2026 真实调参体系，已联网核实）

来源：screen.studio/guide/animations、animations-motion、adding-editing-zooms

| Screen Studio 控件 | 形态 | 关键洞察 |
|---|---|---|
| Zoom level | 滑块 | = Cap `amount` |
| Auto / Manual | Tab | = Cap `mode` |
| **Screen animation: `Focused` / `Smooth`** | 离散二选 | Focused=快速稳定易读 / Smooth=流畅有创意感 |
| **Cursor animation: `Smooth`/`Medium`/`Rapid`/`None`** | 离散档位 | 速度用**语义档**而非裸数字 |
| Motion blur strength | 滑块 | （属 P0-4 运动模糊，不在本 ZoomSegment） |

### ★ 核心设计洞察
**Screen Studio 从不让用户调裸浮点数**，而是用 `Smooth/Medium/Rapid`、`Focused/Smooth` 这种**语义化档位**。这正是 Cap 当前的体验短板——后端是 `glideSpeed=0.5` 这种裸参数。
> **本方案核心增值点 = 把后端裸参数包装成创作者一眼秒懂的语义化档位/开关，而非直接甩一堆 0~1 滑块。**

## 四、字段 → UI 映射设计

把 4 个未暴露字段，按"创作者听得懂的语言"重组为一个 **"动画 / Animation"** 子区，追加在现有 `Zoom` 强度 + `Zoom Mode` 之后。

### 4.1 `glideSpeed`（缩放过渡速度）→ 语义化速度档 + 微调
- **形态**：分段控件（`KTabs` 或 `RadioGroup`）三档 + 可选精细滑块
- **档位映射**（对标 SS 的 Smooth/Medium/Rapid）：
  | 档位 | glideSpeed 值 | 文案 | 图标 |
  |---|---|---|---|
  | Smooth（流畅） | 0.3 | 慢而电影感 | `IconLucideWind` |
  | Medium（标准） | 0.5（默认） | 平衡 | `IconLucideGauge` |
  | Rapid（迅捷） | 0.8 | 快速稳定、易读 | `IconLucideRabbit` |
- **交互**：选档直接 set 对应值；"高级"展开后给 `Slider`（0.1~1.0，step 0.05）精细微调。选档与滑块**双向同步**（滑块值落在档位区间则高亮对应档）。
- **理由**：90% 创作者点档位即可，进阶用户能精调——符合"渐进式披露"。

### 4.2 `edgeSnapRatio`（边缘吸附强度）→ 语义化滑块
- **形态**：`Field` + `Slider`
- **映射**：0（不吸附，画面可贴边）~ 0.5（强吸附，主体强制居中安全区），默认 0.25
- **文案**：`Edge Snap` / 副标 "Keep zoomed content away from screen edges"
- **tooltip 格式**：百分比 `formatTooltip="%"`（0.25 → "25%"，比裸 0.25 友好）
- **图标**：`IconLucideBoxSelect`（边框/安全区语义）

### 4.3 `instantAnimation`（瞬时切换）→ 开关
- **形态**：`Subfield` + `Toggle`（项目标准开关，`bg-blue-500`）
- **文案**：`Instant Zoom` / 副标 "Skip animation, cut directly to zoom"
- **交互逻辑**：开启 `instantAnimation=true` 时，**速度档/边缘吸附置灰**（`disabled`），因为瞬切下过渡参数无意义——这是专业级的"互斥联动"细节，避免用户调了无效参数。

### 4.4 `glideDirection`（退场滑动方向）→ 方位选择器
- **形态**：紧凑九宫格方位控件（中心=None + 上下左右）或下拉 `KSelect`
- **映射**：None（原位淡出，默认）/ Left / Right / Up / Down
- **文案**：`Exit Glide` / 副标 "Slide direction when zoom ends"
- **优先级**：P0.5（最进阶，可放"高级"折叠区，避免面板过长）
- **图标**：方向箭头 SVG（`IconLucideArrow*` 系列，按需 import）

## 五、信息架构与布局（面板结构）

为避免一次性堆太多控件造成认知过载，采用 **"基础常显 + 进阶折叠"** 二级结构（复用项目已 import 的 `Collapsible`）：

```
┌─ ZoomSegmentConfig ─────────────────────┐
│ [基础区 · 常显]                           │
│  ◆ Zoom        ──────●──  2.0x   (amount)│
│  ◆ Zoom Mode   [ Auto | Manual ]  (mode) │
│     └ Manual 焦点拖拽板（Manual 时显示）   │
│                                          │
│ [动画区 · 常显]  ← 本次新增核心            │
│  ◆ Speed       ( Smooth | Medium | Rapid)│  glideSpeed
│  ◆ Edge Snap   ──●──────  25%            │  edgeSnapRatio
│  · Instant Zoom              [Toggle]    │  instantAnimation
│                                          │
│ [进阶区 · 折叠 ▸ Advanced]                │
│  ◆ Speed (fine) ──●──── 0.50             │  glideSpeed 精调
│  ◆ Exit Glide   [ ◌ ↑ ↓ ← → ]           │  glideDirection
└──────────────────────────────────────────┘
```

设计原则（全部对齐 Cap 现有 `ui.tsx`）：
- 用 `Field`（带 SVG icon + name）包主控件，`Subfield` 包开关行
- 速度档用 `KTabs`（与 Zoom Mode 的 Auto/Manual 视觉一致）
- 颜色：填充 `bg-blue-9`、卡片 `bg-gray-2/3`、文字 `gray-11/12`，**零裸色**
- 图标：全部 `~icons/lucide/*` SVG，**禁用 Emoji**
- 间距：沿用 `gap-4`（Field 间）、`space-y-*`

## 六、可直接落地的代码骨架（SolidJS）

> 落地位置：`ConfigSidebar.tsx` `ZoomSegmentConfig` 内，现有 `Zoom Mode` 的 `</Field>` 之后追加。
> 所有 `setProject("timeline","zoomSegments",props.segmentIndex,<field>,v)` 写法与现有 `amount` 完全一致。

```tsx
// === 新增：动画区 ===
const GLIDE_PRESETS = [
  { id: "smooth", label: "Smooth", value: 0.3 },
  { id: "medium", label: "Medium", value: 0.5 },
  { id: "rapid",  label: "Rapid",  value: 0.8 },
] as const;

const currentGlidePreset = () => {
  const v = props.segment.glideSpeed ?? 0.5;
  if (v <= 0.39) return "smooth";
  if (v >= 0.66) return "rapid";
  return "medium";
};

const isInstant = () => props.segment.instantAnimation ?? false;

// --- Speed 档位（glideSpeed）---
<Field name="Speed" icon={<IconLucideGauge class="size-4" />}>
  <KTabs
    value={currentGlidePreset()}
    onChange={(id) => {
      const p = GLIDE_PRESETS.find((x) => x.id === id);
      if (p) setProject("timeline","zoomSegments",props.segmentIndex,"glideSpeed",p.value);
    }}
  >
    <KTabs.List class="flex flex-row items-center rounded-lg relative border">
      <For each={GLIDE_PRESETS}>{(p) => (
        <KTabs.Trigger value={p.id}
          class="z-10 flex-1 py-2 text-gray-11 data-selected:text-gray-12 transition-colors outline-hidden peer"
          disabled={isInstant()}
        >{p.label}</KTabs.Trigger>
      )}</For>
      <KTabs.Indicator class="absolute flex p-px inset-0 transition-transform rounded-[0.6rem] overflow-hidden">
        <div class="flex-1 bg-gray-3" />
      </KTabs.Indicator>
    </KTabs.List>
  </KTabs>
</Field>

// --- Edge Snap（edgeSnapRatio）---
<Field name="Edge Snap" icon={<IconLucideBoxSelect class="size-4" />}>
  <Slider
    value={[(props.segment.edgeSnapRatio ?? 0.25) * 100]}
    onChange={(v) => setProject("timeline","zoomSegments",props.segmentIndex,"edgeSnapRatio", v[0]/100)}
    minValue={0} maxValue={50} step={1} formatTooltip="%"
    disabled={isInstant()}
  />
</Field>

// --- Instant Zoom（instantAnimation）---
<Subfield name="Instant Zoom">
  <Toggle
    checked={isInstant()}
    onChange={(v) => setProject("timeline","zoomSegments",props.segmentIndex,"instantAnimation", v)}
  />
</Subfield>

// --- 进阶折叠：精调 + Exit Glide（glideDirection）---
// 用项目已 import 的 Collapsible 包裹，glideDirection 用紧凑方位按钮组
```

> 注：上方为结构骨架，落地时按现有 KTabs Indicator 动画细节完善（参考 Zoom Mode L3784-3801），确保选中滑块动画一致。档位边界值（0.39/0.66）落地后用真实预览微调。

## 七、为什么这个设计是对的（设计决策依据）

1. **不造突兀轮子**：100% 复用 `Field/Subfield/Slider/Toggle/KTabs` + `gray/blue` token + lucide SVG，新控件和现有面板**像同一个人设计的**。
2. **对标但更友好**：Screen Studio 用语义档（Smooth/Medium/Rapid），我们照搬这个心智，把裸 `glideSpeed` 翻译成档位——比 SS 多给"高级精调"满足进阶用户。
3. **专业互斥联动**：`Instant Zoom` 开启时置灰过渡参数，杜绝"调了无效参数"的困惑。
4. **渐进式披露**：基础常显、进阶折叠，面板不臃肿。
5. **零编译风险**：纯前端 SolidJS + 已存在的后端字段，**不碰 Rust，不依赖 Xcode 全量编译**——正好绕开当前 P0 算法卡在 Xcode 的环境障碍，可独立交付一个"看得见摸得着"的成果。

### 落地相对原方案的微调（实测记录）

| 原方案文案 | 实际落地文案 | 说明 |
|---|---|---|
| Speed | **Transition Speed** | 语义更明确（缩放过渡速度） |
| Edge Snap | **Edge Padding** | 「边缘留白」比「边缘吸附」更贴近创作者心智 |
| Instant Zoom | **Instant zoom** | 大小写规范统一 |
| glideDirection 档「None」 | **Hold**（图标 `circle-dot`） | 「保持原位」语义比「None」更直观 |
| 进阶折叠用「精调 Slider + Exit Glide」 | **仅 Exit Glide**（去掉 glideSpeed 精调滑块） | 简化：档位已覆盖 90% 场景，去掉裸滑块更干净，符合「不甩裸浮点数」原则 |
| 折叠触发 = Advanced 按钮 | **`open={!instant()}` 自动联动** | Instant 开启自动收起方向选择（瞬切下退场方向无意义），更智能 |

> 结论：实现完整度高于原方案（互斥联动 + 自动折叠更专业），且全部复用 Cap 设计 token（`bg-blue-9`/`bg-gray-3`/`text-gray-11/12`）+ lucide SVG，零裸色零 Emoji，与现有面板视觉一致。**待用户指令决定是否 dev 实机预览 / 提交 git**（遵守 worker 铁律未自行提交）。
