> 一句话定位：在「点击自动缩放」基础上叠加**真实 UI 控件矩形**定位，把放大从「跟着光标走」升级为「精准框住你点的那个按钮」——这是 Screen Studio 纯光标架构做不到的超越点。

## 一、背景与目标

### 1.1 为什么做（护城河逻辑）
- **竞品现状（已联网核实，见预研报告）**：Screen Studio 的逐点击自动缩放本质是**纯光标驱动**——每次点击生成一个 zoom 关键帧，配弹簧物理平滑，**既无无障碍树也无视觉识别**。它放大的是「光标所在的点」，不是「光标点中的控件」。
- **Cap 的超越点**：在点击当下用 macOS 无障碍（AX）树反查命中控件的**真实屏幕矩形**，让放大框**精准贴合按钮/输入框/链接**的几何边界，并据其大小自适应放大强度。原生应用上，这是肉眼可见的「更聪明」。
- **永不退步**：AX 拿不到元素（Electron / 浏览器 / canvas / 无权限）时，**自动退回原有点击坐标聚类**（P0 能力），体验只升不降。

### 1.2 产品目标
- **主目标**：原生 macOS 应用录屏场景下，点击触发的放大「框住控件」而非「框住一个点」，提升教程/演示的专业观感。
- **北极星指标**：语义缩放段落占比（`ZoomMode::Manual` 由元素生成的段 / 总自动缩放段）——在「原生应用为主」的录屏中目标 ≥ 60%。
- **不可退让的底线**：任何场景下都不得比 P0（纯坐标聚类）效果差或报错（兜底铁律）。

### 1.3 目标用户
教程作者 / 产品演示 / UP 主 / SaaS 增长团队（与商业化规划一致），核心录制对象为**原生桌面应用**（设置面板、IDE 原生控件、系统偏好、原生工具栏等）。

## 三、功能规格（严格对齐真实实现）

### 3.1 采集层 — AX 反查（`crates/recording/src/cursor.rs`）
- **入口**：`click_element_bounds(coords, display, crop_bounds)`（L741，`#[cfg(target_os="macos")]`；非 macOS 占位返回 `None`，L773）。
- **AX 调用**（`mod ax`，L786）：
  - `AXUIElementCreateSystemWide()` → `AXUIElementSetMessagingTimeout(0.25)`（**单次消息上限 0.25s**，L854，目标 App 无响应也不拖垮高频采集线程）→ `AXUIElementCopyElementAtPosition(x, y, &element)`。
  - 取矩形：**优先 `AXFrame`**（一次拿全矩形，L870）；个别元素仅暴露 `AXPosition`+`AXSize` 时兜底拼装（L873-875）。
  - 内存：所有 +1 引用对象用 `CFType`（create rule）托管，离开作用域自动 `CFRelease`；**零新增 crate 依赖**（直接声明 ApplicationServices C-API）。
- **坐标换算**：元素矩形左上 / 右下两角，各经与光标**完全相同**的 `display→normalize→crop` 链换算到 0–1 UV（L750-759），保证语义矩形与既有光标轨迹严格对齐（含多屏负坐标、Retina 逻辑像素、录制裁剪）。
- **过滤**：`is_meaningful()` 过滤整屏 / 越界 / 零尺寸命中，不合格即降级返回 `None`（L769）。
- **触发时机**：仅鼠标**按下（down）**时触发；`move` 事件零侵入（不影响 16ms/60Hz 采集）。**必须点击当下采集**（AX 反映实时 UI，录完控件可能已消失）。

### 3.2 数据层 — `ElementBounds`（`crates/project/src/cursor.rs` L32-80）
```rust
pub struct ElementBounds { pub x: f64, pub y: f64, pub width: f64, pub height: f64 } // 归一化 0–1 UV
impl ElementBounds {
    pub fn center(&self) -> (f64, f64)      // 元素中心（缩放定位用）
    pub fn area_ratio(&self) -> f64         // 占屏面积比
    pub fn is_meaningful(&self) -> bool      // 有限 & 正尺寸 & width<0.95 && height<0.95
}
pub struct CursorClickEvent { /* ... */ pub element_bounds: Option<ElementBounds> } // serde default + skip None
```
- `element_bounds` 为 `Option` + `#[serde(default, skip_serializing_if = "Option::is_none")]`（L78-79）→ **旧 `cursor.json` 反序列化为 None，新数据不写 None 字段**，双向兼容。

### 3.3 生成层 — 簇 → 缩放段（`apps/desktop/src-tauri/src/recording.rs`）
1. **插值落点**：`place_clicks()`（L3253）给每个 down 点击按 `time_ms` 插值光标坐标，并携带 `element_bounds`（L3263）。
2. **时空双阈值聚类**：`cluster_placed_clicks()`（L3271）—— 时间间隔 ≤ `CLUSTER_TIME_EPS_MS` **且** 空间距离 ≤ `CLUSTER_SPACE_EPS` 才并簇，替代旧版写死的一刀切合并。
3. **每簇 → 一个 `ZoomSegment`**（L3384-3424）：
   - **语义分支**：`element_union()`（L3182）取簇内所有 `is_meaningful` 元素的**并集包围盒** → 中心点定位 `ZoomMode::Manual{x,y}`（clamp 0–1）+ `element_amount()`（L3206）按占屏比反推强度（小控件趋向 `AMOUNT_MAX`，大面板趋向 `AMOUNT_MIN`）。
   - **兜底分支**：簇内无任何有效元素 → `ZoomMode::Auto` + `dynamic_amount()`（密度/散布动态），渲染层跟随光标——**兜底铁律：体验只升不降**（L3400-3412）。

### 3.4 关键参数（真实常量，`recording.rs` L3080-3110）
| 常量 | 值 | 含义 |
|---|---:|---|
| `AMOUNT_BASE` | 1.8 | 坐标兜底基础放大倍数 |
| `AMOUNT_MIN` | 1.5 | 放大下限（语义/兜底共用） |
| `AMOUNT_MAX` | 2.8 | 放大上限（语义/兜底共用） |
| `DENSITY_GAIN` | 0.7 | 兜底：点击密度增益 |
| `SPREAD_PENALTY` | 0.6 | 兜底：点击散布惩罚 |
| `CLUSTER_TIME_EPS_MS` | 1200 | 聚类时间阈值（ms） |
| `CLUSTER_SPACE_EPS` | 0.18 | 聚类空间阈值（归一化距离） |
| `ISOLATED_POST_PADDING_MS` | 1500 | 单击段尾部延时（ms） |
| AX 消息超时 | 0.25s | 单次 AX 调用上限 |
| `is_meaningful` 整屏阈值 | 0.95 | width/height ≥0.95 视为无意义命中 |
| `DWELL_*`（未启用） | 0.05 / 800ms | 停留弱信号，MVP 关闭 |

### 4.1 功能正确性（核心）
| # | 验收项 | 判定标准 | 优先级 |
|---|---|---|:--:|
| F1 | 原生 App 点击按钮 | 生成段为 `ZoomMode::Manual`，中心落在按钮几何范围内（目测放大框「框住」按钮） | ✅ |

## 五、真机验收清单（GUI 实操，逐条勾选）

> 前置：在已授予「屏幕录制 + 辅助功能（无障碍）」权限的机器上运行**集成构建**（见第六节风险，需可用 Xcode 环境）。测试数据用真实点击，验收后删除临时录制。

### 5.1 原生应用矩阵（验命中 + 框选）
- [ ] **系统设置**：依次点「通用 / 声音 / 网络」等左侧条目 → 每次放大框住该条目 → `Manual` 段 ≥ 80%
- [ ] **Finder**：点工具栏图标、侧边栏项 → 小图标放大倍数明显高于大区域
- [ ] **原生 App 工具栏**（如 Xcode/备忘录）：连续点相邻按钮 → 验并集包围盒（F3）
- [ ] **小图标专项**：点一个 ≤24pt 的工具栏图标 → 放大倍数趋近 2.8（F2 上限侧）
- [ ] **大面板专项**：点一个占屏 >50% 的面板内空白可点区 → 放大倍数趋近 1.5（F2 下限侧）

### 5.2 降级矩阵（验永不退步）
- [ ] **VSCode/Cursor（Electron）**：点编辑器内按钮 → 多数降级 `Auto`，**放大仍跟随光标、无报错**（F4/H3）
- [ ] **浏览器网页**：点网页链接/按钮 → 降级正确，无空段
- [ ] **Figma（canvas）**：点画布元素 → 降级正确
- [ ] **桌面空白 / 整屏点击**：→ `is_meaningful` 过滤，按兜底处理（F5）

### 5.3 稳定性矩阵
- [ ] **长录制**：≥10 分钟、≥50 次点击 → 无卡顿、内存平稳、缩放段数量合理（P1/P3）
- [ ] **无响应 App**：人为制造卡顿 App 上点击 → 0.25s 超时降级，录制不中断（P2）
- [ ] **旧工程回放**：打开 MVP 之前的录制工程并重生成 → 正常走兜底（C1）

## 八、上线 / 灰度建议

1. **灰度前置**：必须先在可用 Xcode 环境完成 K1 的整包构建 + 第五节真机清单（至少 5.1 原生矩阵 + 5.2 降级矩阵 + C1 旧工程）。
2. **默认开启、可关闭**：语义缩放对原生应用净增益、对其他场景自动降级，建议**默认开启**；同时在调参面板留「关闭语义、回退纯坐标」开关（兜底已是代码默认行为，UI 仅需显式入口）。
3. **数据观测**：上报「Manual 段占比」与「降级段占比」，灰度期监控 H1 是否达 ≥80%、是否有 R1 退步反馈。
4. **回滚**：功能完全由 `element_bounds` 是否存在驱动，关闭路径 = 不采集元素即全量走 P0，回滚零风险。
